## Historical development audits

Use `python -m scripts.audit_frozen_studies` on the current branch to independently
replay the 990 original development/final/robustness records. It reconstructs
each frozen source fingerprint from historical Git blobs and checks that the
physical/scenario engine still matches. The old study-specific commands
below are archival instructions for their exact original source revisions;
they intentionally refuse source drift on the current development branch.

See the [consolidated completion report](../results/desaulniers/publication_package_v1/FINAL_REPORT.md).
The exact 42 reference schedules and 198 scenarios used by these studies are
archived under `publication_development/frozen_inputs_v1/`. Restore them before
auditing a fresh checkout; restoration validates canonical identities and
physical replay and never invokes a reference optimizer or overwrites a
conflicting cache. The fresh-cache regression tests prohibit regeneration.
The paired Stable V3 development screen did not satisfy its frozen promotion
criterion. No new independent enhanced-method final holdout was opened.

Runtime corrections are explicit switches:
`optimizer_initialization_policy: validated_incumbent_v1` retains the already
validated constructor if search initialization expires; and
`coordination_policy: forced_retained_v1` bypasses MILP only when the retained
route choices are mathematically forced. Both default to `original`.
The matched runtime study is implementation validation, not evidence of
general service superiority.

Separately audited offline witnesses can be selected explicitly using
`reference_policy: mp_witness_v1`. This requires the generated reference
inventory and MP charging. The default `legacy_v1` preserves historical
fleets and scenarios. New witness fleet counts are feasible heuristic upper
bounds; different reference policies must not be mixed within a paired study.
Reference content identifiers and plant replay accompany byte hashes.
Old Git text artifacts accept only proven LF/CRLF transport differences;
compressed raw experiment files always require exact byte hashes.

## Evidence boundaries

The static Desaulniers files under `data/opre.2016.1535-sm-data/` are
unchanged benchmark inputs. Customer releases are generated by this project;
published static route costs are not compared with the online MPC objective.
The original ten-record final audit failure, corrected 270-run final study,
and new robustness study have different protocols and must never be pooled.
The original correction changed independent replay dispatch-time handling,
not the MPC controller, optimizers, objective, or five-second decision limit.

The corrected final protocol uses 18 base instances, DoD 0.25/0.50/0.75,
seed 0, and five matched methods. Its source fingerprint is bound to frozen
code. `scripts.verify_desaulniers_final` checks all raw file hashes,
identities, fixed fleets, exact scenario pairing, outcome copies, budget,
and independent trace replay. The resulting report is in
`results/desaulniers/validation/final_integrity.md`.

The first multi-seed robustness preflight (v2) was found ineligible at
DoD 0.75 for every selected instance, *before any v2 optimizer runs*.
The preserved v2 protocol and `preflight_candidates.md` document this.
The actual v3 selection is the lexicographically first unused, physically
replayed SF/MF instance with enough eligible requests for DoD 0.75 in
each predefined family-size slot. This is an eligibility screen, not an
optimizer-performance screen. V3 uses seeds 1-5, all three DoD levels,
and all five methods on 90 matched scenarios (450/450 audited runs, complete).

From the repository root with Python 3.11+:

```powershell
python -m pip install -r requirements.txt

python -m scripts.analyze_desaulniers_robustness --pilot
python -m scripts.run_desaulniers_robustness_v3 --freeze
python -u -m scripts.run_desaulniers_robustness_v3
python -m scripts.analyze_desaulniers_robustness --v3
```

For unattended local execution with a 12-hour default cap between whole
scenarios, use `powershell -File scripts/run_desaulniers_robustness_v3_unattended.ps1`.
The wrapper appends `results/desaulniers/robustness_v3/resume.log`, resumes
hash-verified records, and leaves a partial manifest if its time cap is
reached. `-MaxHours 0` removes the cap. A worker may run beyond the cap;
it is never interrupted merely to meet the wall-time target.

The coverage checker is checkpointed and reports search failures or timeouts
without declaring infeasibility. The materialization pass preserves
constructed offline route traces under `reference_validation/references/`
for independent physical replay; it does not change the controller cache.
In the completed 168-instance scan, all instances parsed and passed the arc
checks; 120 had replayed SF/MF references, 24 had validated fallback
references, and 24 remained unresolved after the 120-second offline search
limit. A separate SP/MP route-order audit found feasible MP charge witnesses
for 13 instances without SF/MF files, including six of the unresolved 24.
Those witnesses are diagnostic only and do not alter the frozen `K_ref` policy.
The v3 runner reuses only hash-matching raw
records, executes one optimizer per child process, stops on an audit or
identity failure, and records a partial manifest until its planned grid is
complete. Re-run the same command to resume. It never regenerates a raw file
that exists outside the manifest. Each decision retains the five-second
budget; the whole-worker watchdog is separate.

The v3 analyzer audits any existing partial records but refuses to render
cross-method science from an incomplete grid. When complete, it reports
paired contrasts and base-instance-clustered uncertainty, retaining seeds
and DoD repeats within each sampled instance. Descriptive intervals across
several contrasts are not multiplicity-adjusted significance claims.
The complete study has a separate [results interpretation](../results/desaulniers/robustness_v3/RESULTS.md),
Markdown tables in `SUMMARY.md`, and two 300-dpi PNG figures.

## Provenance and limits

`results/desaulniers/robustness_v3/environment.json` records Python,
installed package versions, OS, CPU identifier, logical cores, Git head and
dirty-worktree status, seeds, settings, and source/dataset/config/controller
fingerprints. The historical final protocol did not record a precise CPU
model, so a machine-specific historical timing claim is not supported.
The v3 environment file was captured before the new source was committed:
its Git HEAD and dirty flag describe that snapshot, not the eventual
execution commit. The frozen source SHA-256 in the protocol and every raw
record is the checked code identity. The analyzer confirms it still matches
the committed controller and runner sources.
The local GitHub Actions workflow runs the fast full test suite on Python
3.11 and 3.12 and prints installed package versions. It does not run the
heavy coverage or optimization campaigns.

The paper artifacts under `results/desaulniers/paper_v2/` are derived from
the immutable corrected final study, not from v3. Tables are Markdown and
figures are 300-dpi PNG; no PDF figures are produced. Conditional distance
uses only scenarios fully served by every method. The service-loss report
labels observable trace patterns, not proven causes or proven infeasibility.
